# Legacy USDC parent: compiled runtime comparison

Reviewed 2026-10-13. The preserved official `FRC759Token` source compiles with **Solidity 0.8.12, optimizer enabled, 200 runs** to a runtime that matches the pinned [legacy parent](https://fsnex.net/address/0x6b52048a01c41d1625a6893c80fbe4aa2c22bb54), apart from two 32-byte IPFS compiler-metadata digests. Both runtimes contain 15,419 bytes. Every other byte, including embedded Slice creation code, agrees. This is a metadata-normalized runtime match, not an exact source-metadata verification.

`verification.json` identifies the immutable node response, original request, source hash, compiler package, exact differing byte offsets and normalized hash. `comparison.json` retains the tested unoptimized and optimized results. `compiled-runtime.hex` and `compiler-metadata.json` preserve the successful compiler output. The source itself remains in the [earlier claims package](../2026-10-13-usdc-fusion-claims/comparison-frc759.sol); it is not duplicated here.

To reproduce, install the official npm `solc@0.8.12` package in an ignored working directory with install scripts disabled. Compile that unchanged source as the sole standard-JSON source unit `FRC759.sol`, language `Solidity`, optimizer `{ "enabled": true, "runs": 200 }`, selecting `evm.deployedBytecode.object` and `metadata` for `FRC759Token`. All other compiler settings use that compiler's defaults. Compare the resulting runtime with the retained `eth_getCode` result. The only accepted normalization is zeroing the 32-byte IPFS digest in each exact `a2646970667358221220<32 bytes>64736f6c634300080c0033` metadata trailer, at the recorded offsets in both runtimes. Do not strip arbitrary suffixes or ignore opcode differences.

The matched source's parent `_mint` increments its `_totalSupply`; parent `_burn` burns the full-time child without decrementing the parent counter. `sliceByTime` burns the full-time balance and mints complementary dated children; `mergeSlices` burns continuous slices and may mint an appropriate remaining/full-time interval. These mechanics explain why the parent's supply counter and separate child supplies must not be summed into customer claims. Address one has no special transfer/burn branch in this source; its balance is not an automatic zero-address burn.

This comparison does not validate constructor arguments, current owner/controller permissions, beneficial ownership, economic treatment of address-one balances, or whether the old and newer tokens duplicate claims. The node code and state share the project owner's Fusion infrastructure. The deployed metadata's IPFS fetch returned HTTP 429 and is retained separately; its contents were not obtained. No transaction was sent.
